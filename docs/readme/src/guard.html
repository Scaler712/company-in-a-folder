A rule in a text file is not a lock

So the kit ships a real one. A typed yes approves one card, once.

1How a yes works

In Claude Code, .claude/hooks/guard.py runs before every tool call.
STEP 1
You type yes C-7
A hook reads the words you typed and records the yes in a log the AI is blocked from writing.
STEP 2
The AI calls a tool that sends
Before the call runs, a second hook looks at the tool and what it is about to do.
STEP 3
The guard checks two things
Is there a card C-7 for this tool? Is there a typed yes for C-7 that has not been used?
STEP 4
One action goes through
The yes is spent. The same call a second time is blocked.
typed by a person
one yes, one action

2Blocked

Each of these has a test in tests/test_guard.py.
✕a yes C-9 the AI wrote into the card log itself
✕"yes to everything"
✕"ok", "looks good", a thumbs up
✕a repeat of an action whose yes was already spent
✕any write to the guard's own files or the approvals log

3Blocked even with a yes

The hook stops these whatever was approved.
✕deleting outside output/
✕sending to more than 3 people at once
✕a bulk send or a call that names a campaign
✕git clean, git reset, git rm
Its limits, said plainly
It is pattern matching, it runs only in Claude Code, and it is not a sandbox. Changing a price and accepting terms are written rules for the AI, not something the hook can see.
